You are reviewing **PlayMate**, a live early-stage web app. Please read this whole file first, then
`CLAUDE.md` (code rules) and `docs/PROJECT_HISTORY.md` (decisions and history).

**Your job:** a complete, honest critique — code quality, security, correctness, performance, UX/UI, product.

---

## 1. What PlayMate is

A **teammate finder for gamers** ("Stop playing solo. Find your squad.").

- **Profile:** a player makes a profile per game: region / country / city, languages, mic, platform and game-specific
  fields (mode, rank, role…).
- **Matching:** PlayMate shows a ranked deck of compatible players with a match % and the reasons for it.
- **Like and squad:** you like or skip players. When **both** players like each other they become **squadmates**, and
  only then can they see each other's in-game name and Discord.
- **Users and stage:** the first users are Persian-speaking gamers (Battlefield 6 first), but the UI is English and
  global. Very early: about 5 real profiles, no marketing yet. It is a solo-founder project, built first with ChatGPT
  and then with Claude Code.

Live site: **https://playmate-api-aamc.onrender.com**

## 2. Stack and hosting

- **Backend:** Python **FastAPI** — a single `main.py` (~960 lines), plus `games.py` and `locations.py`.
- **Frontend:** plain HTML/CSS/JS, no framework and no build step.
  - Pages: `landing.html`, `ui.html` (the app), `profile.html`, `legal.html`, `404.html`.
  - Assets: one JS/CSS pair per page in `static/`. Cache busting with `?v=N`; HTML is sent with `Cache-Control: no-cache`.
- **Supabase:**
  - **Postgres** (tables `profiles`, `likes`, `blocks`).
  - **Auth**: email + password; the browser uses supabase-js 2.45.4 with the anon key.
  - The backend verifies the Supabase **JWT (HS256)** with `SUPABASE_JWT_SECRET` and talks to the DB with the
    **secret/service key**. RLS is on for all tables, and the browser never talks to the tables directly.
- **Hosting:**
  - **Render** free web service, auto-deployed from GitHub `PouriyaMHA/playmate-mvp`, branch `main`.
  - Free-tier sleep is avoided by a cron-job.org ping to `/health?deep=1` every 10 minutes. A GitHub Actions
    keep-alive is the backup.
- **Images:**
  - Original SVG art is generated by `tools/gen_art.py`.
  - Official game cover JPGs are in `static/img/games/photos/`, taken from official store/press pages and credited as
    trademarks of their owners.
  - Illustrated avatars `avatar-13..25.webp` were made with Gemini.

## 4. Data model (Supabase)

- **`profiles`:** one row per **user + game** (unique `user_id, game`).
  - Columns: `username` (lowercase, same for all of a user's games) and `display_username`, `region`, `city`,
    `platform`, `mic`, `languages` (csv codes).
  - Private columns: `in_game_username` and `discord_username`.
  - Activity: `last_active`, `looking_until`.
  - `game_meta` jsonb: `{fields: {...}, country, avatar}`.
  - Old Battlefield-only columns: `favorite_mode`, `class_type`.
- **`likes`:** `from_user_id`, `to_user_id`, `game`. A mutual pair = squadmates.
- **`blocks`:** `blocker_id`, `blocked_id`, `game`, `reported`, `reason`. A block hides both people from each other
  in **every** game.
- **Account-level data:** bio, banner, avatar, links, referral and referral_count live in the Supabase auth user's
  `app_metadata.playmate`. Only the server can write it, and updates **merge** keys. The avatar is also copied into
  each profile's `game_meta.avatar`, so match lists need no per-player auth lookups.

## 5. Key rules and design decisions (please check they hold everywhere)

1. **Identity comes only from the JWT `sub`.** Never from bodies or query params.
2. **`in_game_username` / `discord_username`** may only be returned to the owner (`/api/my-profile`) and to mutual
   squadmates (`/api/my-squad-details`). Never in match results, public profiles, pending likes, etc.
3. **Every user-provided value rendered with `innerHTML` must go through `esc()`.**
4. **The browser only has the anon key;** all DB access goes through the API.
5. **Matching** (`score_pair` in `main.py`): region 35, same country +5, same city +5, shared languages 15–20, both
   voice 10, same platform 5, plus per-game field weights. Role-like fields (`match="diff"`: LoL role, FC position,
   BF class) score when **different**. Score is capped at 100.
6. **Hard filters** (`can_play_together`):
   - GTA Online: no crossplay.
   - EA SPORTS FC: Switch is separate.
   - Minecraft: Java vs Bedrock edition must match.
   - LoL: server must match.
   - Blocked users and people I already liked are hidden.
7. **"Looking now"** lasts 1 hour by default (max 3 h, set via `/api/looking`) and puts the player first in other people's decks.
8. **Small-user-base UX:**
   - No minimum score.
   - Player counts are hidden until a game has 25+ players (50+ on the landing page).
   - A smart empty state instead.
9. **Account deletion** (`DELETE /api/account`, `confirm: "DELETE"`) removes profiles, likes, blocks and the auth
   user.

## 6. Known gaps and limitations (already on our list — still tell us if you see better ways)

- **Supabase "Confirm email" is OFF** (on purpose until public launch).
- **Terms/Privacy are drafts** and there is no support email yet.
- **No custom domain yet,** so no transactional email: no "someone liked you" or "you matched" emails.
- **No chat.** Squadmates contact each other via the in-game name / Discord.
- **Placeholders:** profile photo upload and Highlights. The Verified/Legendary badges are placeholders too.
- **Single `main.py` file;** no automated test suite in the repo (we test with ad-hoc scripts against a local server).
- **Free hosting:** Render free tier and Supabase free tier.
- **Scaling:** matching loads up to 800 candidate rows per request and scores them in Python. Fine for now; tell us
  where it would break.

## 7. What we want from you

Please produce a **written report** (Markdown) with findings grouped and ranked **Critical / High / Medium / Low**.
For each finding give the file:line, a concrete failure scenario, and a suggested fix.

1. **Security and privacy:**
   - Auth: JWT verification, `aud`/`exp` handling.
   - IDOR: can anyone read or change another user's data?
   - Leaks of private fields (IGN/Discord, emails).
   - XSS: any `innerHTML` without `esc()`.
   - RLS assumptions, rate limiting / abuse (like spam, report spam, referral abuse).
   - Account deletion completeness, CORS, headers, secrets handling.
2. **Correctness:** matching and scoring edge cases, mutual-like logic, block logic across games, crossplay filters,
   the location validation, race conditions in the frontend (polling, game switching, double clicks), token refresh.
3. **Performance and scalability:** DB queries per request, N+1 patterns, the 800-row matching scan, polling load,
   free-tier limits.
4. **Code quality and maintainability:** structure of `main.py` and `ui.js`, duplication, naming, error handling, what
   to split first, and which tests to add first.
5. **UX/UI critique of the live site** (please actually use it, desktop and phone width):
   - The first-time visitor journey: landing → sign up → first profile → first match.
   - Empty states, mobile layout, accessibility (contrast, keyboard, screen readers), copy/wording, trust signals.
6. **Product critique:**
   - Would this get and keep users?
   - What is missing for a launch to a gaming community?
   - What would you cut?

## 8. Ground rules (important — this is production)

- **Don't push to `main`.** It auto-deploys to the live site. Don't open PRs either unless asked. Just write the
  report (e.g. `docs/CODEX_REVIEW.md`).
- **The local `.env` points to the production Supabase project.** Don't run anything that **writes** to the database:
  no signups, likes, profile saves, deletes or SQL. Read-only code reading is fine. If you run the app locally, only
  open pages and don't log in or submit forms.
- **On the live site you may browse freely** (landing, `/u/pouriya`, `/terms`). Please **don't create accounts or send
  likes/reports** without asking the owner first.
- **Never print, copy or commit secrets** from `.env` (`SUPABASE_KEY` is the service key).
- English UI copy is intentional (global audience), so it is not a finding by itself.
