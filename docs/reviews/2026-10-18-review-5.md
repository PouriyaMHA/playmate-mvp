## New findings

### R5-M01 — Medium: changing an avatar can silently roll back a successful game-profile edit

**Location:** `main.py:188–195` (`sync_profile_avatar`), called at `:1133`; game-profile upsert at `:660`.

Avatar propagation reads each complete `game_meta`, modifies its avatar key, then writes the whole old object back. A concurrent profile save can succeed between that read and write and have its new mode/rank/country overwritten.

**Deterministic offline repro, pinned `ac59fa3`, fake DB, real API handlers:** create CS2 with Premier / Gold Nova. PUT an avatar change. Immediately after sync's `select("id,game_meta")` has produced its result, inject a normal POST `/api/profile` changing the fields to Competitive / Silver, then resume sync. The nested POST returned **200 with Competitive / Silver**; the avatar PUT returned **200**; subsequent GET `/api/my-profile` returned **Premier / Gold Nova**, with the new avatar. No production race or direct production database write was attempted.

**Suggested fix:** change only the avatar JSON path atomically (or normalize account avatars so this propagation is unnecessary). If using optimistic concurrency, detect/retry a changed `game_meta`; do not overwrite unrelated keys from a read snapshot. Add this interleaving to API tests and later real-DB coverage. This is a separate lost-update path in profile-row propagation, beyond the previously documented `app_metadata`/referral merge problem M05.

### R5-M02 — Medium: valid long contact names break the populated mobile Squad page

**Location:** `static/css/ui.css:1032`, `:1062–1072`; contact markup in `static/js/ui.js:1140–1163`.

**Live repro:** on C's own CS2 profile, save a 40-character unbroken IGN and Discord (accepted with 200). A and C are mutual. At **375×812**, open A's app, choose CS2 and the **Squad** bottom tab. `document.documentElement.scrollWidth` became **622** for `innerWidth=375`; C's IGN extended to x≈586 and the squad card to x≈601. After removing C's profiles and reloading, the same page returned to **375/375**. Users must scroll sideways to read/access this squad layout. The committed phone test has no mutual contacts and never selects this populated tab.

**Suggested fix:** allow contact text to wrap anywhere, and ensure grid/flex ancestors and squad cards can shrink to the viewport. Check copy controls and match dialogs with the longest allowed names. Add a populated Squad mobile assertion after readiness, not just the app's initial state.

### R5-M03 — Medium: one metadata request failure strands game selection without a retry

**Location:** `static/js/ui.js:469–476`, `:505–511`, `:520–522`; retry action at `:1556`.

**Repro in Chromium on the live app, injecting one browser network failure:** start in loaded CS2; abort only the next `/api/meta/gta` request; choose GTA through Switch game. The URL/state says GTA, the visible game bar still says Counter-Strike 2, Find stays disabled, `gameReady=false`, and `loadFailed=false`. Only a transient “Could not load this game” toast appears. Reopen the picker and choose GTA again: **zero retry requests**, because the same-game early return fires. There is no Try again control. Reload successfully recovers.

**Suggested fix:** render a persistent game-load error with a working retry, and permit retrying the current game when it never became ready. Keep the R4 submission guard. Clear/replace stale game chrome while loading. Cover metadata rejection and recovery in the browser suite.

### R5-L01 — Low: Looking now remains visibly active after it expires

**Location:** `static/js/ui.js:1321–1330`, `:1460–1471`.

**Live repro:** set one minute through the documented own-account `/api/looking` API and reload the app. Initially the button correctly says “1 min left (tap to stop)”. **109 seconds later**, both own-profile and public-profile APIs said `looking_now=false`; the open page still had class `looking-btn on` and showed that same active message. The default one-hour status has the same missing rerender path. Polling refreshes social data, not the owner's button/countdown.

**Suggested fix:** rerender the local status/countdown on a small timer and visibility changes, using the stored expiry; keep the server authoritative. Add an expiry browser test using a controlled clock.

### R5-L02 — Low: a rejected old poll displays a connection warning over a healthy new game

**Location:** `static/js/ui.js:1084–1088`, inside `startSocial`.

**Live-browser injected-failure repro:** hold A's GTA poll; switch to CS2 and let its profile/social requests succeed. The new game was ready and the network banner was hidden. Abort the held GTA request: **“Connection issue. Some features may not work.”** appeared on CS2. Success handling has generation checks; this catch unconditionally calls `showNetError` for the obsolete request.

**Suggested fix:** guard that error rendering with `isCurrent(gen)` too. Add old-poll rejection after a successful new-game poll to the suite. This is a residual stale-error path, not a failure of the specific repaired R4 Like catch.
