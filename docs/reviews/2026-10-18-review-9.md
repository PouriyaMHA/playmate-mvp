# Review 9 — Steam profile link

Reviewed **2026-10-18**, current `main` **`5e9d193`**, including the deployed feature at https://playmate-api-aamc.onrender.com and migration 007.

## Verdict

**Changes requested: one Medium and three Low findings.** The privacy boundary and outbound-link safety passed the checks below. No Critical/High finding, confirmed contact leak, XSS, or open redirect was found. Numeric validation needs correction; prefill and the contact reminder also need small fixes before considering the feature complete.

## Findings

### R9-M01 — SteamID64 validation uses a decimal prefix instead of the account-ID range

- **Severity:** Medium
- **Location:** `main.py:149–150`, `main.py:167–176`
- **Reproduction:** Save an otherwise valid CS2/PC profile with friend code `2039734271`: live returns **200**, storing `profiles/76561199999999999`. Change it to `2039734272`: live returns **422**, although the conversion is `76561200000000000`. Friend code `4294967295` and the corresponding SteamID64 `76561202255233023` also return **422**. Conversely, `76561190000000000` returns **200**, even though it is below the individual desktop-account base; `0` is accepted and becomes the base itself.
- **Cause/impact:** `^7656119\d{10}$` rejects part of the representable public individual-account range and accepts numbers outside it. The bad optional value prevents the entire profile save. These boundary examples demonstrate format/range correctness, not that those particular accounts exist. Valve defines AccountID as 32 bits in its [CSteamID implementation](https://github.com/ValveSoftware/GameNetworkingSockets/blob/master/include/steam/steamclientpublic.h).
- **Fix:** Parse ASCII decimal input and validate the numeric account ID. For this public individual desktop-profile format, require `1 <= friend_code <= 0xffffffff`, or equivalently `1 <= steamid64 - STEAM_ID64_BASE <= 0xffffffff`. Apply the same check to bare IDs and `/profiles/` URLs; emit canonical ASCII digits. Add lower/upper-bound and prefix-transition tests rather than restricting IDs to the current-looking decimal prefix.

### R9-L01 — Unicode numeric input can throw a 500 or save an unusable link

- **Severity:** Low
- **Location:** `main.py:150`, `main.py:169–170`; `static/js/ui.js:687–688`
- **Reproduction:** Live `POST /api/profile` for CS2/PC with `steam_profile: "²"` returns **500**, rather than a validation error. Python's `isdigit()` accepts this character, but `int()` raises `ValueError`. Separately, an isolated execution of the actual validator accepted `7656119١١١١١١١١١١` and returned `profiles/7656119١١١١١١١١١١`: Python `\d` accepts these digits, whereas `steamUrl()` permits only ASCII. That second case was reproduced locally without importing the app or accessing its environment.
- **Impact:** Malformed input escapes the intended 422 handling; another accepted numeric representation cannot produce a frontend Steam link. No shared-service outage or data leak was demonstrated.
- **Fix:** Use ASCII `[0-9]` full matches, normalize only explicitly supported representations, and return 422 for all other inputs. Cover superscript digits, non-ASCII decimal digits and mixed scripts, including the save-to-render round trip.

### R9-L02 — Prefill loses Steam when the first existing game has no Steam contact

- **Severity:** Low
- **Location:** `static/js/ui.js:658–663` (also the shared-cache update at `static/js/ui.js:767–771`)
- **Reproduction:** On the live QA account, arrange saved games in the returned order `['lol', 'cs2']`, with a saved Steam link on CS2. Open CS2 and confirm its field contains `https://steamcommunity.com/id/qa9steam2`. Switch to a new Helldivers 2 profile and select PC: the Steam row appears, but its value is **empty**. The first alternative profile, LoL, contains `steam_profile: null`, so prefill never examines CS2. Saving CS2 first does not solve this selection rule: the first profile response replaces the cached shared object, including its Steam value. Saving an unsupported game also writes null to the shared Steam cache.
- **Impact:** A user with a Steam contact already saved must enter it again; behavior depends on which game happens to be first. Existing saved per-game links are not deleted by merely switching games.
- **Fix:** Obtain a nonempty Steam value from the owner's eligible saved profiles independently of the source used for location/mic fields. Keep the owner/generation guards. Do not let an unsupported game's null value erase the Steam prefill candidate; preserve intentional clearing of an eligible game's link. Add a regression with LoL first, CS2 second and a new Steam game, plus a fresh-device case.

### R9-L03 — Steam-only contact still triggers the “add contact” reminder

- **Severity:** Low
- **Location:** `static/js/ui.js:775–776`
- **Reproduction:** Save CS2 with a valid Steam profile and empty IGN/Discord. Live saving succeeded and the field showed the canonical Steam URL, but the toast said **“Tip: add your Steam name or Discord so squadmates can reach you”**. The same account's Steam contact had already rendered successfully in another QA account's squad and mutual-match modal.
- **Impact:** The reminder incorrectly implies that the newly supported contact method is insufficient, nudging users to disclose another identifier unnecessarily.
- **Fix:** Include a valid saved `steam_profile` in the contact-presence condition and mention Steam in the reminder when offered. Base this check on normalized saved data. Test Steam-only, IGN-only, Discord-only and no-contact profiles.

## Disagreements / design judgment

1. **Do not treat a familiar decimal prefix as Steam identity validation.** The advertised friend-code/SteamID64 support requires numeric range checks; the boundary repro and Valve definition above contradict the current approach.
2. **The first arbitrary game is not a reliable source for a shared Steam prefill.** Preserve per-game privacy/visibility, but choose the owner's Steam prefill independently rather than assuming the first game's null means no Steam account exists.
3. **Steam is a complete contact option for this feature.** The existing IGN/Discord-only reminder should not survive unchanged. Also replace “lets squadmates add you in one click” (`ui.html:199`) with “lets squadmates open your Steam profile”: the current action opens a profile and still requires Steam's own friend-add flow. This is a copy recommendation, not an additional security finding.
4. **Keep the canonical path and fixed HTTPS-origin design.** I agree with this choice and with keeping private contacts in the atomic social snapshot. Migration 007 adds the column without weakening grants; the existing snapshot serializes the added column automatically, and live mutual reads confirmed that it reaches the API.
