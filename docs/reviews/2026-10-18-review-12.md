## Findings and concrete fixes

### N1 — Medium: F9 moves the overlap bug to “Show everyone”

**Locations:** `main.py:1005–1011`; `static/js/ui.js:1087–1094,1890–1893`.

**Live reproduction:** A has Rocket League in `fa`; B has it in `en`. B is the only candidate. Skip B, enable Same language only, then scan. Response: `matches:[]`, `filtered:1`, `skipped:0`, `complete:true`. UI says **“1 player would show up without…”** and offers **Show everyone**. Click it. The handler clears the filters but retains B in `exclude`; response is `matches:[]`, `filtered:0`, `skipped:1`. UI now offers **See the 1 player you skipped**. The promised first recovery produced no player. Looking-only has the same predicate overlap.

The original review-11 reproduction now chooses the filtered branch instead of the skipped branch; it still requires two separate recovery actions to reveal the promised candidate. Moving exclusive counters around cannot make both actions independently truthful.

**Fix:** calculate recovery counts under exactly the predicates each action will retain, or deliberately clear the relevant overlapping exclusions in an accurately labelled combined action. For example, count `filtered` recovery only among non-skipped/non-liked compatible candidates, then offer another action when both filters and skips must be reset. Cover the complete overlap matrix for language, Looking now, skips and likes. Also qualify filtered/liked “everyone” titles when `complete:false`; the new completeness flag is currently used only in the incompatible/zero branches.

### N2 — Medium: F7 leaves stale validation state and misses initial focus

**Locations:** `static/js/ui.js:553–620,637–700,839–863,925–961`; `ui.html:148,232`.

**Reproduction A — partial correction:** enter empty CS2 setup and press Next. Alert says `Please fill in: Region, Country, Mode, Rank, Languages`. Select a region. Region's invalid flag clears, but the visible persistent alert still lists Region. `clearInvalid()` only hides the summary after the last invalid class disappears; it does not recompute its text. It also clears on any input/change, including an edit back to an invalid empty value.

**Reproduction B — new regression from this patch:** open a new Minecraft setup with valid shared prefills; press Next without platform/edition/mode/style. Alert says `Please fill in: Platform, Edition, Mode, Playstyle`. Switch to an already valid saved CS2 profile. Live state says **Saved ✓**, while the old alert remains visible and `#platform` remains `aria-invalid=true` although its CS2 row is hidden. Removed Minecraft controls no longer exist. Neither game initialization nor form rebuilding resets the newly persistent error state.

**Reproduction C — original remaining requirement:** on fresh live wizard entry, `document.activeElement` is **BODY**, including on phones. Next/Back use `goToStep()` and focus the heading; initial entry calls `renderWizard()` directly and does not. Platform also lacks required/aria-required semantics despite being required when multiple platforms exist.

**Fix:** keep validation state scoped to the current form generation, reset summary/classes/invalid/error associations when rebuilding/loading a game, and recompute the remaining invalid controls and summary after edits. Retain invalid state until the actual value is valid. Focus/announce the initial wizard heading after the phone tab is selected, and expose required platform state. Add partial-fix, clear-again and invalid-game → valid-game browser assertions; complete the real screen-reader pass before signing off the compound accessibility criterion.

### N3 — Low: F2 placement ignores responsive breakpoint changes

**Locations:** `static/js/ui.js:240–246,620,1796–1798`; `static/css/ui.css:2245–2250`.

**Live reproduction without calling the placement helper manually:** start a phone wizard on Profile with a shared-player intent. Resize to **812×375**, switch to another game and back to Minecraft, then resize to **375×812**. Rendering at 812px has moved `#intent-strip` to `#match-panel`. After returning to portrait, `body.dataset.view === 'profile'`; the strip remains in Match and is invisible. Clicking Profile again recovers it. Fixed-size initial entry also works at 320px; the responsive failure was demonstrated on returning to 375px.

**Fix:** call `placeIntent()` when the 760px media query changes, preserving the selected tab and keyboard focus, or put the strip in a shared region outside panel visibility. Add the landscape game-switch → portrait assertion. This is an incomplete F2 repair, not a separate claim that the original static placement already handled rotation.
